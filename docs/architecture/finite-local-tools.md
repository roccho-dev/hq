# Finite local tools

`hq.local-tool.v1` is the first bounded implementation child of
`roccho-dev/adrs#211`. It adds one generic target to the existing canonical
instruction, managed-worker, adapter, and `result.v1` path. It does not add a
queue, runner lifecycle, or durable evidence family.

The ownership boundary is:

```text
selected world JSONL
  hq.local-tool.v1 (meaning, action, bounds)
    -> stable primary binding_ref + expected contract
    -> optional finite named dependency bindings
    -> one binding_executable argv atom per exact dependency use

selected profile
  absolute world_path
  absolute executable_bindings_path
    -> envctl.verified-executable-bindings.v1
    -> immutable absolute executable + digest + deployment identity
    -> contract-v2 finite ordered environment + configuration digest

managed worker
  Prepare(request) verifies exact action/input/primary/dependencies
    -> required finite run-view provider opens or execution fails closed
    -> durable started result.v1 with exact provider evidence
       + replaceable run-view provider/native terminal evidence
    -> re-hash primary and used dependencies immediately before launch
    -> separated direct argv with exact dependency path substitution
    -> bounded stdout/stderr/stdin/timeout
    -> canonical terminal result.v1
```

World data never contains an executable path, command string, shell syntax,
PATH lookup, working-directory discovery, ambient environment inheritance,
branches, loops, or a workflow graph. The queued payload contains only exact
tool ID, tool version, action ID, and typed input. Primary and dependency
binding references remain world data and are not copied into the queue.

## Finite semantics

- `argv` entries are exactly one `literal`, required typed `field`, or
  `binding_executable` that names one declared one-level dependency.
- A dependency declaration contains only a stable name, binding reference, and
  expected binding contract. It cannot contain actions, children, environment,
  discovery, or recursion.
- Only dependencies referenced by the selected finite action are resolved.
  Read/observe actions therefore do not resolve or execute an unused child.
- input types are `string`, `integer`, `boolean`, and finite `enum`.
- stdin is `none` or one required string field with an explicit byte limit.
- output is `text`, one JSON value, or JSONL.
- JSON/JSONL output may declare a fixed `final` selector so canonical completion
  stores a compact structured result instead of the raw provider stream.
- a native session selector is a fixed list of object-field segments. For JSON
  it reads the sole value; for JSONL it reads the last non-empty record. It is
  not JSONPath, a regular expression, or an expression language.
- lifecycle is `one-shot` only. A start action completes at the provider's
  bounded handoff/native-reference response; it does not claim that the child
  interactive process exited.
- approval is `explicit` only. The existing digest-bound worker approval is
  intentionally stronger than local-tool risk metadata.
- contract version 1 has an explicitly empty process environment.
- contract version 2 has one finite sorted environment and the exact
  domain-separated `configurationDigest` generated by envs. No ambient merge is
  performed.
- metacharacters remain literal argv bytes; no shell is involved.
- An action may declare one `policy=required` run view by exact tool version and
  action ID. That view action receives only required string inputs `view_id`,
  `run_id`, and `events_path`, cannot recursively declare another view, and must
  return a native session reference. Missing or invalid view infrastructure
  yields `view_unavailable` before the selected action executes.

`binding_contract_version` is required. An envs profile may supersede the same
stable binding reference; hq rejects a registry entry whose contract version,
deployment, executable digest, environment digest, or used dependency evidence
differs from the world and durable `started` evidence.

## Recovery and evidence

The `started` provider evidence contains the primary binding identity and,
when present, its configuration digest plus ordered used dependencies. Each
dependency records name, provider ID, contract, deployment, executable kind,
material digest, and optional configuration digest.

Recovery compares this complete structure. A missing, reordered, stale, or
tampered dependency and any primary configuration drift are non-green. The
worker never treats a syntactically valid but content-wrong digest, including an
all-zero digest, as proof.

## Migration boundary

Dedicated Herdr, Codex, and Claude adapters remain registered as compatibility
references. The generic local-tool path now also supports a required,
reconstructible run-view projection; the selected profile decides whether
Herdr or another exact finite provider supplies that projection. This slice
does not add Vim provider semantics, migrate other providers, install Herdr, or
change worker supervision.
