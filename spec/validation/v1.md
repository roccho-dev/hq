# Validation row v1

## Purpose

`validation.v1` is append-only rejection evidence for an input line that cannot become a valid `instruction.v1` row.

It is separate from `result.v1` because invalid input may have no valid instruction id, target, or run identity. A worker records validation evidence before skipping a rejected line and continues reading later lines.

## Row shape

| key | required | type | rule |
|---|---:|---|---|
| `version` | yes | string | Exactly `validation.v1`. |
| `source_line` | yes | positive integer | One-based line number in the consumed instruction stream. |
| `status` | yes | string | Exactly `blocked`. |
| `error` | yes | object | Non-empty `code` and `message`. |
| `instruction_id` | no | non-empty string | Present only when a valid id was parsed. |
| `target` | no | string | Present only when a valid target was parsed. |

Unknown fields fail validation in v1. `error.retryable`, when present, is boolean.

## Relation to result rows

- Valid instructions may later produce `result.v1` rows, including a policy or runtime `blocked` event.
- Invalid input lines produce `validation.v1`, not a fabricated run.
- Validation rows never create a session projection.
- Processing continues after a rejected line so later valid instructions remain visible.
