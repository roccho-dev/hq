# verified-resource invocation v1

This is a strict `instruction.v1` payload form for `target=local-tool`, `op=run`. It does not define another instruction, queue, worker, executor, or result version. It reuses the existing `worker.approval.v1` contract as a separate explicit dispatch permission.

## Payload

Required keys, exactly:

| key | type | meaning |
|---|---|---|
| `tool_id` | non-empty string | selected resource identity |
| `tool_version` | non-empty string | exact selected resource version |
| `policy_version` | non-empty string | exact selected invocation-policy version |
| `argv` | non-empty string array | ordered arguments passed directly to the verified executable |

Finite action payload keys (`action_id`, `input`) and invocation payload keys (`policy_version`, `argv`) are mutually exclusive.

The queue never carries an executable path, command string, binding registry path, deployment ID, environment, credential, account, profile, endpoint authority, cwd, stdin, or shell setting.

## Admission and dispatch

1. The instruction must pass the existing strict `instruction.v1` contract.
2. Its exact digest includes all four payload fields.
3. `hq.submit` is queue admission only for this payload form and does not create dispatch approval.
4. Missing approval produces `worker.policy.v1 status=approval_required`, one `result.v1 kind=accepted`, zero `started`, and zero process start.
5. An unchanged held instruction produces no repeated durable held evidence.
6. `hq approve --profile <name> --instruction <id> --approved-by <identity>` appends one exact `worker.approval.v1` row to `<workspace>/.hq/approvals.jsonl`.
7. An identical approval repeat is an idempotent no-op. A conflicting approval for the same instruction identity fails closed.
8. A later exact approval resumes the same queued run ID.
9. Finite named actions retain the existing submit-derived approval behavior.
10. Stale approval and policy/resource/binding failures remain non-green and start zero process.
11. Provider evidence is recorded before execution through the existing `result.v1 started` row.

## Resource policy

The exact selected `hq.local-tool.v1` definition supplies:

- `policy_version`;
- `max_argv` and `max_arg_bytes`;
- bounded timeout/stdout/stderr;
- denied options;
- denied argument prefixes.

A denied long option matches its exact spelling, `--option=value`, and every syntactic long-option abbreviation that could resolve to it. Ambiguous abbreviations fail closed. Shell punctuation has no special meaning because execution uses separated argv through the existing direct process API.

## Excluded

Shells and command strings, PATH lookup, cwd/environment input, secrets, interactive input, PTY/TUI, generic SSH/OCI, workflow graphs, autonomous submit, and automatic finite-action promotion are outside v1.
