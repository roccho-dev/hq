# Result row v1

## Purpose

`result.v1` is the append-only observation boundary for a worker run. A reviewer must be able to reconstruct acceptance, start, output, final answer, failure, and the exact provider used without opening a TUI or relying on terminal scrollback.

## Required fields

| key | type | rule |
|---|---|---|
| `event_id` | non-empty string | Unique event identity. |
| `version` | string | Exactly `result.v1`. |
| `run_id` | non-empty string | Stable for one worker attempt. |
| `instruction_id` | non-empty string | Links to one `instruction.v1` row. |
| `target` | string | One of `sh`, `herdr`, `codex`, `claude`, `host`, `local-tool`. |
| `kind` | string | Event kind below. |
| `seq` | integer | Starts at `0` and increases by one inside a run. |
| `recorded_at` | RFC3339 UTC string | Must end in `Z`. |

Optional shared field:

- `native_session_id`: non-empty string. Once present for a run, it must not change.

Optional `started`-only field:

- `provider`: exact capability/provider/contract/deployment/kind/integrity identity durably written before the external invocation.
- `view`: optional `run-view.v1` evidence for a required, replaceable run view opened before execution. It contains `policy=required`, the exact view provider evidence, and its non-empty native terminal reference.
- `configuration_digest`: optional exact digest of provider-owned finite process configuration.
- `dependencies`: optional ordered exact one-level executable dependencies. Each item contains the stable dependency name, provider ID, contract, deployment, kind, integrity digest, and optional configuration digest.
- Readers accept historical dependency items without `name`; newly prepared provider evidence must include it.
- `idempotency_contract` and `idempotency_key` appear together only when the provider proves deduplication across the effect/result ambiguity window.
- A concrete executable path is deployment data and is not copied into canonical instruction meaning or provider evidence.
- For `local-tool`, `provider` records the exact primary binding reference as provider ID together with the expected binding contract, selected deployment, executable kind, and verified material digest. The envctl registry schema is transport metadata, not the provider kind.
- For binding contract 1, configuration is empty and `configuration_digest` is absent. Contract 2 records the envs-generated domain-separated digest of the exact ordered environment.
- Only dependencies used by the selected finite action appear. A declared but unused dependency is neither resolved nor recorded.

## Event kinds

| `kind` | projected status | required detail |
|---|---|---|
| `accepted` | `queued` | none |
| `started` | `running` | optional exact `provider` evidence |
| `stdout` | unchanged (`running`) | `message` string |
| `stderr` | unchanged (`running`) | `message` string |
| `completed` | `completed` | `final` object containing non-empty `text` and/or `path` |
| `failed` | `failed` | `error` object |
| `blocked` | `blocked` | `error` object |
| `timeout` | `timeout` | `error` object |
| `cancelled` | `cancelled` | `error` object |

An `error` object contains non-empty `code` and `message`; optional `retryable` is boolean. An ambiguous post-effect/pre-result crash is represented by a non-green `blocked` event with `error.code=reconcile_required` unless the exact provider binding proves a reusable idempotency key contract.

Unknown event kinds and unknown fields fail validation.

## Run invariants

- `seq=0` is `accepted`.
- `instruction_id` and `target` do not change inside a run.
- `started` occurs at most once during the initial invocation and is durable before provider effect.
- When the selected action declares a required run view, execution fails closed with `view_unavailable` unless the view opens first; the subsequent `started` row records its exact provider and native terminal reference.
- A run view is a projection only. Closing it never changes canonical run state, and the same canonical evidence can reconstruct it without re-executing the provider action.
- Recovery from a `started` run does not append another `started` event.
- `stdout` and `stderr` occur only while the run is `running`.
- A run has at most one terminal event.
- No event follows a terminal event.
- Completed output is preserved in `final`; errors are preserved in `error`.
- File order is not the only ordering signal; `seq` is authoritative inside one run.
- A stale lease or process death is not proof that the provider effect did not occur.
- Primary and dependency executable bytes are re-hashed immediately before effect.
- Automatic resume is permitted only when the complete provider structure matches: primary identity, deployment, integrity digest, configuration digest, ordered dependencies, idempotency contract, and idempotency key.
- Missing, reordered, stale, or tampered dependency evidence and primary configuration drift fail closed.
