# Instruction row v1

## Purpose

`instruction.v1` is the durable worker-input boundary. `hq` may compile and append this row, but it does not execute the row, select an adapter, or grant execution authority.

```text
editor -> hq -> instruction JSONL -> worker -> adapter
```

The row is append-only input data. A worker must validate it before policy, approval, redaction, claim, or adapter dispatch.

## Row shape

| key | required | type | rule |
|---|---:|---|---|
| `id` | yes | non-empty string | Unique within the consumed instruction stream. |
| `version` | yes | string | Exactly `instruction.v1`. |
| `op` | yes | string | Exactly `run` in v1. |
| `target` | yes | string | One of `sh`, `herdr`, `codex`, `claude`. |
| `payload` | yes | object | Exact target payload defined below. |
| `created_at` | yes | RFC3339 UTC string | Must end in `Z`. |
| `reason` | no | non-empty string | Human-readable intent. |
| `policy` | no | object | Reserved for the bounded policy contract; in v1 it must be empty. |
| `reply_to` | no | non-empty string | Prior instruction id when this is a follow-up or retry. |
| `labels` | no | array of non-empty strings | Search and grouping metadata only. |

Unknown top-level or payload keys fail validation. A new field requires a contract change rather than a hidden adapter default.

## `sh` payload

```json
{"argv":["printf","hello\n"],"cwd":"."}
```

- `argv` is required and is a non-empty array of non-empty strings.
- `cwd` is optional and is a non-empty string.
- Shell command strings, implicit expansion, and hidden environment defaults are not part of v1.

## `herdr` payload

Herdr operations use the official agent CLI and keep agent-specific command arguments typed.

### Start

```json
{
  "action":"start",
  "name":"reviewer",
  "cwd":".",
  "split":"right",
  "no_focus":true,
  "command_argv":["claude","-p"],
  "prompt":"Review the issue and return evidence."
}
```

The adapter invokes `herdr agent start <name> ... -- <argv...> <prompt>`. `name`, `command_argv`, and `prompt` are required. `split` is `right` or `down`.

### Read, observe, and attach mapping

```json
{"action":"read","agent":"reviewer","source":"recent-unwrapped","lines":100}
{"action":"observe","agent":"reviewer","wait_status":"idle","timeout_ms":120000}
{"action":"attach","agent":"reviewer","takeover":false}
```

`agent` is a Herdr agent target or name. Read and observe persist output through the common adapter port. Attach records a typed interactive target; the worker does not enter an interactive terminal.

## `codex` payload

```json
{
  "action":"exec",
  "prompt":"Validate the worker fixtures.",
  "cwd":".",
  "output_path":".hq/final/codex.txt",
  "sandbox":"workspace-write",
  "skip_git_repo_check":false
}
```

```json
{
  "action":"resume",
  "prompt":"Continue from the prior evidence.",
  "session_id":"thread-id",
  "cwd":"."
}
```

- `action` is `exec` or `resume`.
- `prompt` is required.
- `session_id` is required only for `resume`.
- `output_path`, when present, is relative to `cwd` and cannot escape it.
- `sandbox` is `read-only`, `workspace-write`, or `danger-full-access`.
- Worker context owns timeout and cancellation; adapter payload does not create a second retry or timeout policy.

## `claude` payload

```json
{"action":"print","prompt":"Summarize the evidence.","cwd":".","output_format":"json","max_turns":3}
{"action":"resume","prompt":"Continue.","session_id":"session-id","output_format":"stream-json"}
{"action":"background","prompt":"Run the long review.","name":"long-review","cwd":"."}
{"action":"logs","session_id":"session-id"}
{"action":"attach","session_id":"session-id"}
```

- `print` and `resume` use non-interactive output; `output_format` is `json` or `stream-json`.
- `resume` requires `session_id`.
- `background` assigns a deterministic run-bound UUID and records it as a native-session hint.
- `logs` persists recovered text.
- `attach` records the typed interactive command target but does not launch an interactive TUI.

## Validation and failure

- Malformed JSON, missing required keys, duplicate ids, unknown versions, unknown targets/actions, unsupported fields, and non-empty `policy` objects fail closed.
- Input that cannot become a valid instruction produces append-only [`validation.v1`](../validation/v1.md) evidence with `status=blocked`; it does not fabricate a run or session.
- A valid instruction denied after validation may produce a `blocked` `result.v1` event.
- A rejected line must not hide later lines; every line is read and reported independently.
- Provider output is transient until the worker maps and redacts it into canonical `result.v1`.

## Authority boundary

- `hq` owns compile-ready suggestions and append-only acceptance.
- The worker owns validation, run identity, policy application, adapter selection, result identity, and durable append.
- Adapters own only provider commands, parsing, transient output, completion, and native-session hints.
- `session.v1` remains a replaceable projection from canonical instruction/result evidence.
